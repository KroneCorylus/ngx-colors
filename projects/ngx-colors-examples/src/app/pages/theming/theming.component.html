Theming

Theme the picker

ngx-colors ships a light and a dark theme out of the box, and every surface is driven by a CSS custom property so you can repaint it to match your product without overriding a single component style.

How it works

Every color in the panel reads from a --ngx-colors-* custom property with the light value baked in as the fallback:

Set the token anywhere up the cascade and the panel picks it up; leave it unset and the light default applies. There is nothing to import — no theme file, no mixin, no build step.

The one thing to know: the panel overlay is appended to <body>, outside your component's DOM. So component-scoped styles and wrapper classes around the trigger never reach it. Tokens have to come from a global stylesheet — either on :root (all pickers) or via overlayClass (one picker). Both are shown below.

Global vs per-picker

Every picker: set the tokens on :root in a global stylesheet.

One picker: put the tokens in a class and pass its name to overlayClass. The class is stamped on the body-attached overlay, so — unlike a wrapper element — the tokens actually reach it.

Custom theme

This picker uses overlayClass="brand-theme", a purple theme defined in this site's global stylesheet. Open it — the surface, text, borders, selection ring, corner radius, and shadow all follow the tokens.
